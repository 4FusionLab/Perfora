# Contributing to Perfora

Keep geometry independent of Fusion. `Perfora/geometry.py` contains layout and clearance logic; `model.py` and `clipping.py` adapt it to Fusion; `preview.py` renders previews; `Perfora.py` owns the command and dialog.

Curved sources use `surface_geometry.py` for dependency-free placement/finite-tool separation and `surface.py` for a shared temporary preparation consumed by preview, fixed output and Feature. Renderer-owned native sheets never enter a final-build cache. `cylindrical.py` retains the legacy fixed-cylinder adapter for older API callers.

Run `python3 -m unittest discover -s tests -v` and `python3 install.py --zip`. Run `fusion_surface_regression.py` in Fusion: all 13 shapes, Trim on/off, cylinder/cone/freeform, exact rim samples, 3D Sketch on a moved axis, existing openings, circular placement/angle/offset/spread, operations, bounded zones, inner/outer walls and dense cached preview. `fusion_surface_feature_regression.py` uses the actually loaded add-in to test changing hole counts, natural parameter/radius/height dependencies, local F3D reopen and subsequent zone editing. Keep source, operation and target dependencies acyclic.

Run `fusion_surface_ui.py` from Fusion's Python console with `mode='fast'` and `'full'`. After real OK/Cancel call the returned `finish(True/False)`; `stage='ready'` is not transaction acceptance. Check common planar/curved controls, Seed/New Pattern, real Edit Feature OK/Cancel, Undo/Redo, and change Distance during Full Preview before cancelling. The command validates against its original captured chart during provisional cuts. Source changes reset that chart. Verify source document geometry remains untouched. Legacy cylinder-only geometry is covered separately by `fusion_cylindrical_regression.py`; its old UI acceptance is superseded by `fusion_surface_ui.py`.

Run `tests/fusion_height_regression.py` with the tested add-in running for upstream face resizing: a 2 mm shell with side perforation and `h` changing 70 → 20 → 70 → 20 mm. Cover rounded/unrounded Voronoi, Trim to Boundary on/off, nonzero Edge Offset, Circle, and native Extrude/Cut. Check every owned feature (especially Combine), the visible body's validity, solid volume and height, natural recompute, and `computeAll`; a Healthy Custom Feature alone does not establish a valid result.

CAD changes also require real Fusion checks. Install the add-in and run `PerforaSmokeTest` from Scripts and Add-Ins. From Fusion's Python console, use an absolute path into your checkout or extracted ZIP:

```python
import runpy
runpy.run_path('/absolute/path/to/Perfora/tests/fusion_shapes_regression.py')
```

Other scenarios: `fusion_clipping_regression.py`, `fusion_preview_performance.py`, `fusion_voronoi_regression.py`, `fusion_dialog_regression.py`, and `fusion_ui_contract.py`. The Voronoi suite checks exact preview/sketch contours, cache invalidation, a translated and rotated plane, an annulus, a concave boundary, rounded-hole areas/volumes, tiny bevel absorption, tangent corners after trimming, and all five operations with rounding. The dialog checks require the add-in to be running. Run `fusion_feature_regression.py` against the registered add-in from the same checkout: Custom Feature definitions require its manifest UUID and cannot be validated by importing a standalone test package. Review each script before running it. CAD scenarios create a separate unsaved document; test reports are written outside the repository.

Before release, verify command startup, all 13 shapes, including Voronoi, fast/full previews, boundary trimming, Cancel without residual geometry, Cut, Undo/Redo, document save/reopen, and native Extrude editing. For Voronoi, check Seed/New Pattern, 0% and 100% Irregularity, minimum web, Round Corners on/off, radius changes, and cache invalidation after changing a setting. For Feature, check parameter and upstream-boundary changes, different hole counts, user-parameter expressions, Edit Feature OK/Cancel, Full Preview rollback, Undo/Redo, and native archive reopen with subsequent recompute. Source, operation, and target bodies remain fixed during edit; the initial mode supports straight Distance extents and Join/Cut/Intersect/New Body. Record the Fusion version, OS, and actual results; geometry tests alone do not establish CAD correctness.

The Feature regression also builds and recomputes all 13 shapes, checks offset/direction bounds, and rejects unsupported extents, taper, and New Component. To test an installed copy, pass its registered folder with `init_globals={'addon_path': '/absolute/API/AddIns/Perfora'}`. Start a fresh Fusion session and load only that copy: switching linked copies with the same manifest UUID in one session can retain the first Custom Feature owner's registration and report that its extension is not running. A reload from the same path and a clean launch are separate checks.

For UI acceptance, run `fusion_ui_contract.py` with `init_globals={'result_mode': 'profiles'}` for Sketch, `'extrude'` for Extrude, or `'feature'` for Feature. Add `'registered_command': True` to exercise the installed `DiegoV_Perforator` command. After clicking the real OK or Cancel button, call `finish(True)` or `finish(False)` in the returned namespace; a report at `stage='ready'` alone does not prove the transaction passed. Keep each report before starting another scenario.

Keep the command ID, add-in UUID, and document attribute namespace stable unless a deliberate migration is implemented. Use Conventional Commits, for example `fix: preserve clearance around inner boundaries`.


For Circular distribution, run `fusion_circular_regression.py` as well: all 12 repeating shapes, ring placement and contour agreement, cache invalidation, a translated/rotated plane, annular trimming with Edge Offset, panel volume, and all five native operations. In the dialog, check Start Radius, Fixed/Radial orientation, Tangential orientation, Start Point selection/clearing, offsets relative to the picked point, switching to/from Voronoi, Fast/Full Preview, OK, and Cancel without residual geometry. Noncircular rings use conservative enclosing bounds; Start Radius measures hole centers, not a guaranteed solid hub.

Numeric inputs use native StringValueCommandInputs backed by hidden ValueCommandInputs because ValueCommandInput hides empty edits behind its last valid expression. `fusion_ui_contract.py` checks default restoration for all numeric fields, unitless integers, explicit zero, invalid nonempty text, units, and document parameters. Also clear a visible field in the UI, wait for its default to return, then clear and immediately type a replacement; test a command cancellation with a pending reset and ensure no late callback affects another document.

For point-based Circular placement, run `fusion_center_regression.py`: preview/sketch agreement, anchor replacement and clearing, cache reuse, projected points on a translated/rotated plane, vertex/construction points, assembly coordinates, tangential trimming/extrusion, and Feature dependency recompute where supported. In the real dialog, select a point, switch distribution and shape, test Fast/Full Preview, OK and Cancel; in Edit Feature, replace/clear the point and verify both commit and cancellation.

Global Start Point and Spread Radius must work for Staggered, Rectangular, Circular, and Voronoi. Check zero/unlimited radius, a point off the Profiles plane, positive radius with/without Trim to Boundary and Edge Offset, radius-driven Feature recompute, and bounded performance on a large source. Numeric default coverage follows the current dialog controls.

For optimization work, run `fusion_optimization_regression.py` with the registered add-in. It checks shared cells with current Extrude parameters, lazy Panel switching, retry after a real Boolean target mutation, separate source/inset/spread invalidation, a moved source plane, and Feature cache/recompute. Optional `baseline_path` points to a frozen pre-change Perfora package for paired native geometry/timing comparisons. Do not package that snapshot. Run the normal shape, clipping, Voronoi, circular, origin, preview, dialog, and Feature regressions as applicable; finish with real Full Preview, OK and Cancel.

Only immutable 2D cells cross Fast Preview/final build through `GeometryCache`. Native clipping bodies remain renderer-owned; final CAD rereads its source and performs its own exact trim. Do not cache output bodies, extrusion configuration, or rolled-back source sketches. The single-source cache holds one successful entry and is cleared with the command.

Multi-region development adds up to 32 command-local cache slots, each holding one successful immutable 2D layout. Renderer-owned source sheets and insets can be reused while source revisions and margin stay valid. Final CAD never reuses those native sheets. Offline `test_multi_region.py` tests frame/phase rules, schema-1 compatibility, mapping, cache invalidation, and fault-injected cleanup/restoration using inert API doubles; this does not establish native kernel or command transaction correctness. After explicit authorization to use Fusion, run `fusion_multi_region_regression.py` from this exact registered checkout, then `fusion_multi_region_ui.py` for Sketch/Extrude/Feature with both real OK and Cancel. Follow [the full multi-region acceptance checklist](docs/MULTI_REGION.md), including Edit Feature, shared Cut targets, mapped Intersect, Undo/Redo, local F3D save/reopen, and existing single-source regressions. These scripts were prepared offline and have not been run in Fusion.

For sketch profiles drawn directly on solid faces, run `fusion_profile_face_regression.py`: horizontal/vertical support, inner loops, Trim to Boundary on/off, Fast Preview/profile/Cut agreement, timeline restoration, and Feature recompute after editing the source diameter and hole size. Run `fusion_ui_contract.py` with `source_profile=True` and `registered_command=True` for automatic Objects selection, Full Preview, actual OK and Cancel without residual geometry.

Stable acceptance: run `fusion_release_acceptance.py` from the Fusion Python console with `result_mode='feature'`, then repeat with `'extrude'`. Use the registered add-in from that checkout (or pass `addon_path`). After real OK call `verify_created()`, perform native Undo and call `verify_undo()`, perform native Redo and call `finish()`. The final check edits a model parameter, exports/reopens a local F3D, recomputes again, and restores the original document. Local archive reopen is distinct from cloud save/reopen.

Run `scripts/benchmark_layout.py --repeat 3` to reproduce current geometry scenarios. Historical before/after samples, methodology, baseline fingerprints, and caveats live in `docs/BENCHMARKS.md`. Product screenshots are generated in real Fusion with `scripts/capture_release_examples.py`; inspect every exported image before publication.

For imported/trimmed curved faces, use the face evaluator for both UV bounds and evaluations: the standalone analytic geometry may use a different angular origin. `fusion_surface_face_regression.py` copies a chosen body from the open design into a disposable document, excludes faces already covered with many openings, checks more than ten holes on each regular large face, preview membership and optional native Cut/rim agreement (`build=True`), and verifies the original revision/timeline remain unchanged. Reports stay outside the repository. The regression includes a conical Rectangular/Staggered difference test. The command hides Circular and Pattern Angle on curved sources and removes Spread Radius globally; saved legacy Feature parameters retain recompute compatibility.

`fusion_surface_spacing_regression.py` audits physical row lengths on large NURBS faces in the open design without modifying it. Independent dense polyline measurements must vary by less than 0.2% for equal row-coordinate increments. The pure `LengthMap` tests include strongly nonuniform parameter speeds and inverse/extrapolation checks. Conical rows must retain shared generator phases in addition to differing between Rectangular and Staggered. `fusion_surface_ui.py` with `kind='selected'`, `source_body_name` and `source_face_id` snapshots an actual finite face into a disposable design and checks precise sweep initialization, including preselection. Never round a finite sweep through `formatInternalValue` before validation.

`fusion_layout_ui.py` checks the reported 50×50 mm square (5 mm holes, 1.5 mm web, 3 mm edge offset) and a pointed 50 mm base / 90 mm height cone in a disposable document. Launch from the native Python console with `kind="plane"` or `kind="cone"`, call `check_preview()`, use the real OK/Cancel buttons, then call `finish(created)`. The square must retain central symmetry and six sites on its first ring; the cone density must adapt per row instead of inheriting its narrowest circumference. `fusion_surface_regression.py` also checks pointed-cone density, native Cut, preview/final count agreement and cone Feature recompute.

For a NURBS face with a collapsed parameter boundary, `fusion_surface_face_regression.py` accepts `chart_only=True` for the constructor reproduction, then `hole_limit=5000, build=True` for full placement and native Cut. Validate the regular interior, exclusion of local pole envelopes, preview/rim agreement, and unchanged source revision/timeline. Keep spheres and tori excluded.
For the unreleased layout variants, see [LAYOUT_VARIANTS.md](docs/LAYOUT_VARIANTS.md). Run `test_layout_variants.py` and `test_layout_contracts.py` offline; `scripts/benchmark_layout_variants.py` records pure geometry timings. Native CAD coverage is in `fusion_layout_variants_regression.py`. Run `fusion_ui_contract.py` with `layout_variant='contour'/'fan'/'phyllotaxis'/'poisson'/'wave'/'chevron'/'running_bond'/'between_curves'`, each result mode, and real OK/Cancel before `finish`. Native Edit Feature OK/Cancel, old archive reopen, guide dependency recompute, Undo/Redo, and exact clipping remain mandatory gates. Do not infer CAD acceptance from the offline doubles.
Along Path is development-only; native acceptance is recorded in the integration report. Offline contracts live in `test_curve_layout.py` and `test_curve_integration.py` (the latter uses fake API objects and is not CAD acceptance). Native checks: `fusion_curve_regression.py` and `fusion_ui_contract.py` with `distribution='path'`, `registered_command=True`, and each result mode, followed by actual OK/Cancel and `finish`. The full pending matrix, numerical thresholds, API references, Feature compatibility limits and unresolved CAD assumptions are in [CURVE_LAYOUT.md](docs/CURVE_LAYOUT.md). Do not run these scripts until the shared Fusion session is explicitly available. The integrated dialog currently has 58 numeric fields.


## Integrated release branch

Use `tests/fusion_release_integration.py` for the surface/distribution matrix, mixed-source rejection, multi-surface Cut and parameter-driven recompute of cylinder/cone/freeform Feature. Each case uses a disposable document. `tests/fusion_integration_archive.py` exports a temporary local F3D containing multiple cylindrical regions and Along Path, reopens it, and changes their parameters again. These do not establish cloud-save or Windows CAD behavior.

Reload through the registered Script's native stop/run lifecycle. Executing the entry module from another script can register the Custom Feature under the wrong owner and leave a healthy node without working recompute. Check actual volume changes, not health alone. When testing upstream sketch edits, roll before the Feature, edit the sketch, then move the marker to the end, matching Fusion's normal Edit Sketch workflow.

`fusion_layout_variants_regression.py` accepts `layouts` and `shapes` subsets for bounded runs. Keep the full report before another run overwrites it. For native UI acceptance retain separate reports for real OK and Cancel; stage `ready` is not acceptance.

`fusion_release_selection.py` verifies native preselection: a cylinder/cone pair retains one compatible source with a notice, while two cylinders retain both. Click the real Cancel before `finish()`. `fusion_release_ui.py` accepts surface kind, region count, layout and result mode; use `prepare()` from the native Python console after opening through MCP, then `preview()`, real OK/Cancel and `finish()`. See the integration report for the executed matrix.


## Organic fields (development)

See [ORGANIC_PATTERNS.md](docs/ORGANIC_PATTERNS.md). Run the complete offline suite including `test_organic.py`, `test_solid_topology.py` and the actual dialog method contracts. In Fusion run `fusion_organic_regression.py` against the registered checkout, with optional `kinds`, `shapes`, `modes` and `trims` subsets. `archive=True` tests local F3D import/recompute; `capture=True` exports real viewport images. Keep reports outside the repository. An active document is never a fixture: each case creates a disposable document and restores the original.

Use `fusion_organic_ui.py` from the native Python console for each shape and affected result mode. Call `prepare()`, request Fast/Full with `preview()`, then `check_preview()`. Click the actual OK/Cancel button and call `verify(created)`. For Feature, run `begin_edit()`, then `edit_preview()`, click the actual OK/Cancel button and call `end_edit(accepted)`. Native Undo/Redo must be followed by `verify_undo()` / `verify(True)`. `finish()` restores the user's original document. A ready stage or Python geometry pass alone is not native transaction acceptance. Recheck zero-border material connectivity, seam/depth separation, inner cutouts, multiple homogeneous regions and current packaging.
