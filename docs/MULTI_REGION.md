# Несколько плоских областей

**Обновление интеграции:** реализация включена в `codex/release-features`. Исторический офлайн-статус ниже описывает исходную ветку; текущие CAD/UI-результаты и совместимость поверхностей фиксируются в [RELEASE_INTEGRATION.md](RELEASE_INTEGRATION.md).

Статус: разработка в `codex/multi-region`, без выпуска и без CAD/UI-проверки в Fusion. Основа — Perfora 1.0.1, коммит `66770428663f61abd4c6daf2c556c57be3c405ce`. Цилиндрический режим и изменения других веток не включены. При офлайн-разработке не использовались работающий Fusion, его MCP/UI, установка дополнения, регистрация или общие настройки.

## Пользовательское поведение

В штатном поле **Profiles** выбираются до 32 плоских граней и замкнутых профилей одного экземпляра компонента. Допускается смешивать грани и профили. Конструкционная плоскость используется только отдельно. Все настройки общие, **Maximum Holes** — общий предел, а не предел каждой области. Если хотя бы в одной области не остаётся отверстий, вся операция отклоняется. Пустые области не пропускаются молча.

Sketch создаёт по эскизу на область; Extrude — по штатному выдавливанию. Feature создаёт один элемент Perfora с общей группой параметров и отдельными зависимостями источников. При Edit Feature можно менять параметры, тип профиля, Start Point и толщину; состав источников, операция и Objects остаются фиксированными.

Повторное указание той же native-сущности исключается после проверки экземпляра компонента. Разные сущности с совпадающей или частично перекрывающейся заполненной областью отклоняются. Это включает выбор грани вместе с профилем внутри неё. Проверяется исходная область, до Edge Offset и Spread Radius: эти параметры не превращают неоднозначный выбор в допустимый. Точное пересечение временных плоских BRep учитывает внутренние вырезы; область внутри существующего выреза допустима, если материал не перекрывается. Соседство по ребру допустимо, границы не сливаются, Edge Offset сохраняется у каждой области.

## Привязка раскладки

Для одного уникального источника действует прежнее поведение: автоматический центр габаритов в системе исходного эскиза либо Start Point. Даже массив из одного источника использует старый путь.

Для двух и более источников система строится в координатах компонента, отдельно для каждой плоскости:

1. Нормаль вычисляется из явного базиса `sketchToModelSpace`. Её наибольшая по модулю координата делается положительной; при равенстве приоритет X, затем Y, затем Z. Это делает оси независимыми от направления нормали исходной грани.
2. Начало — ортогональная проекция начала координат компонента на плоскость. X — нормированная проекция оси X компонента. При `abs(normal.x) >= 0.9` используется проекция Y компонента. Y дополняет правую систему.
3. Копланарные области используют одну численную систему. Строгий допуск расстояния между плоскостями — `1e-7 cm`, угловой критерий — `1 - abs(dot(normals)) <= 1e-10`. Точный BRep-контур не заменяется полигональной аппроксимацией при построении или обрезке.
4. Если выбран Start Point, точка проецируется на каждую плоскость и заменяет начало. Для сеток/Voronoi X/Y Offset работают в повёрнутых осях Pattern Angle; для Circular — в указанных осях плоскости. Spread Radius использует тот же центр с учётом сдвигов.

Из этого следуют общая фаза сетки, одинаковые Voronoi-ячейки при одном Seed, один центр колец Circular на копланарных областях и независимость от порядка выбора/габаритов областей. Изменение размеров границы не перемещает начало нескольких областей. Разные плоскости получают предсказуемые локальные оси, связанные с компонентом. Поворот самой плоскости через порог выбора оси может изменить ориентацию сетки — это правило текущей привязки, а не сохранённая пользовательская система координат.

Направление выдавливания следует **исходной нормали эскиза каждой области**, как в одиночном пути. В Feature диапазон временного выдавливания меняет знак при противоположной нормали общей системы; это должно совпадать со штатным Extrude. Для противоположных граней нужен Full Preview. Оси привязки не означают общего глобального направления выдавливания.

## Операции и Objects

| Результат | Допустимое поведение при нескольких областях |
| --- | --- |
| Sketch | Holes / Perforated Panel, все формы, Trim to Boundary, Edge Offset и внутренние вырезы |
| Extrude / New Body | По отдельному выдавливанию на область в компоненте источников; направления/протяжённости/конусность штатного Extrude |
| Extrude / Join | Штатный выбор соприкасающихся тел средствами Fusion, как в одиночном сценарии |
| Extrude / Cut | По одному опорному/явно сопоставленному телу на область; одно тело может обрабатываться несколькими областями |
| Extrude / Intersect | Одно сопоставленное тело на область, без повторного использования тела |
| Feature | Distance, нулевая конусность, One Side / Two Sides / Symmetric, Capture Design History |
| Feature / Join, Cut, Intersect | Явное сопоставление, как ниже; Intersect без повторного тела |
| New Component | Несколько областей отклоняются; одиночный Extrude сохраняет эту операцию |

Грань и профиль, начерченный непосредственно на грани тела, сопоставляются с опорным телом. Оно должно быть в Objects. Для свободного профиля допускается ровно один Object. Несколько свободных профилей могут вырезать одно общее тело. Неиспользуемые Objects и неоднозначные сопоставления отклоняются; близость тел и пересечение их габаритов не используются для догадок. Objects должны принадлежать компоненту источников; разные явно выбранные assembly context отклоняются до потери proxy-ссылок.

Последовательный Intersect по одному телу означал бы пересечение результатов разных областей и мог бы удалить нужный материал. Поэтому такое сочетание отклоняется. Для нескольких областей нужны разные Objects либо другой режим. При пересчёте Feature сохраняет первоначальные индексы сопоставления, вместо нового поиска опорного тела на изменённой топологии.

## Данные, кэш и отказ

`regions.py` содержит чистую математику без `adsk`. `multi_region.py` читает источники в согласованной системе, готовит раскладки и точные временные контуры, проверяет пересечения и строит выход. Внутренние единицы — cm/rad; runtime-зависимостей не добавлено.

Каждой области выделяется ограниченный слот `GeometryCache` с одним успешным набором неизменяемых 2D-ячеек. Ни выбранные сущности, ни временные тела туда не попадают. Renderer отдельно хранит исходные временные листы и inset: изменение источника/его revision перечитывает лист, изменение margin сбрасывает inset. Цвет, тип профиля и параметры глубины не пересчитывают раскладку. Изменение геометрических настроек пересчитывает ячейки, но может сохранить лист и inset. Общая Custom Graphics рисуется пакетно в компоненте. Reset/закрытие команды освобождает графику, планы и все слоты. Full Preview/OK заново читает источники и точную обрезку; из Fast Preview переиспользуются только подходящие 2D-ячейки.

До первого Extrude готовятся все выходные эскизы, чтобы Boolean не уничтожил ещё не прочитанную исходную грань. До добавления тел Feature готовятся все временные solid. Журнал созданных объектов удаляется в обратном порядке при ошибке. Штатная команда сохраняет транзакционный execute/executePreview; Cancel должен откатить её целиком. Для compute без транзакции предварительно готовятся все новые тела, а перед обновлением каждого BaseFeature копируется его прежнее исходное тело. Ошибка пытается восстановить все затронутые базы, включая отказавшую. Отказ восстановления сообщает ошибку Feature, а не выдаёт успешный результат. Реальное поведение ядра и зависимых Combine требует CAD-проверки.

Новые записи Feature используют schema 2: `source_count`, зависимости `source0…sourceN`, `_body_map` и `_source_count`. Старые schema 1 с `source`, а также одиночные origin-plane Feature читаются старым путём. При редактировании одиночного элемента schema может стать 2, но он сохраняет одиночную структуру зависимостей. Отсутствующий источник/тело, неизвестная схема или повреждённое сопоставление дают явную ошибку. UUID, command ID, CustomFeatureDefinition ID и атрибуты `DiegoV.Perforator` не изменены.

## Что подтверждается офлайн

`tests/test_multi_region.py` проверяет чистую геометрию, общую фазу всех форм, Circular, повёрнутые/зеркальные базисы, внутренние вырезы, лимиты, сопоставление, schema 1/2 и управление кэшем. Для оркестрации используются изолированные инертные подмены API: отказы второй области, удаление всех созданных объектов, восстановление баз после неудачного updateBody, отказ до записи тел и зависимости всех источников. Эти проверки **не подтверждают** работоспособность native API, точного BRep-пересечения/обрезки, Custom Feature или кнопок диалога.

Context7: сначала resolve для Autodesk Fusion 360 API, затем query по выбору нескольких источников и зависимостям. Результат не содержал нужных сигнатур. Попытка открыть официальные страницы Autodesk вернула недоступные страницы. Дополнительно прочитаны установленные на диске `API/Python/defs/adsk/core.py` и `fusion.py`: `setSelectionLimits`, `addDependency`, `setStartAndEndFeatures`, `BaseFeature.startEdit/finishEdit/updateBody`. Работающее приложение при этом не запрашивалось. Привязка через PlaneFrame, точный Boolean плоских листов, сохранность ссылок нескольких Combine и откат сгруппированных узлов остаются предположениями до приёмки.

ZIP собирается штатным `install.py --zip`, без установки в пользовательский API-каталог. Версия manifest остаётся 1.0.1: имя локального ZIP не делает его релизом 1.0.1. Не публиковать и не использовать как замену выпущенного архива до отдельного решения о версии и приёмке.

### Автоматизированные CAD-сценарии

Запустить `tests/fusion_multi_region_regression.py` через `runpy.run_path` из Python Console после подготовки зарегистрированной копии из этой ветки. Скрипт создаёт и закрывает свой несохранённый документ, восстанавливает активный документ пользователя, сохраняет отчёт вне репозитория. `only_cases` позволяет ограничить прогон именами случаев.

- Все 13 форм, Trim off/on, два кольцевых профиля с внутренними вырезами; Fast Preview без оставшихся эскизов, одинаковые ячейки при обратном порядке выбора, площади Sketch и объём native Extrude.
- Смещённая вертикальная плоскость и горизонтальный профиль; разные согласованные системы, отсутствие смещения выходных контуров.
- Повторы, перекрывающиеся профили и искусственная ошибка второй области: исходный объём, число эскизов и таймлайн не изменяются.
- Feature Cut двух профилей на одном теле, сохранённое сопоставление и пересчёт после изменения размера отверстий.
- Feature New Body с двумя кольцевыми источниками и скруглённым Voronoi: чтение schema 2 и изменение толщины.
- Cut/Join/Intersect в Extrude и Feature по двум телам, Objects в обратном порядке: оба тела меняются правильно, Feature хранит индексы `[[1], [0]]` и пересчитывается.

### Настоящий диалог и транзакции

Для каждого `result_mode='profiles'`, `'extrude'`, `'feature'` запустить `tests/fusion_multi_region_ui.py` через `runpy.run_path` и сохранить возвращённое пространство имён. Скрипт открывает штатный зарегистрированный Perfora с двумя профилями на одном теле. Он **не нажимает OK/Cancel** и не объявляет готовый диалог успешной транзакцией.

1. Вызвать `preview('fast')`, осмотреть оба контура и текст привязки; вызвать `preview('exact')`, проверить обе области и объём. Повторить переключение Fast/Full.
2. Нажать реальный Cancel, затем `finish(False)`. Проверка должна подтвердить исходный объём, число эскизов/узлов и неизменность документа пользователя.
3. Повторить сценарий, нажать реальный OK и вызвать `finish(True)`. Проверить все выходные эскизы/операции; для Feature — один узел и две зависимости.
