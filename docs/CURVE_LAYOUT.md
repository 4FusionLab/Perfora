Development branch only. This change starts at Perfora 1.0.1 and has **not** been run, installed, registered, reloaded, or visually inspected in Fusion. The manifest/release version is unchanged. Local numerical and adapter tests do not establish native CAD correctness.

## User contract

Choose **Distribution → Along Path**, then select **one Path**: a sketch line, arc, circle, fitted/control-point spline, or a BRep edge whose geometry is a line, arc, circle, or NURBS. The entire bounded curve must lie on the Profiles plane and belong to the same component. Paths do not have to be inside the boundary. The existing boundary, inner openings, Edge Offset, Trim to Boundary and Perforated Panel behavior still constrain the result. Elliptical curves, multi-segment chains, branched/disconnected paths and cross-component paths are not supported in this first stage. One native selection is allowed; no implicit chaining or projection is performed.

- **Path Spacing**: positive center-to-center distance measured along the curve, independent of hole dimensions and Web Thickness. This is fixed spacing; the last interval is never silently redistributed.
- **Start Offset / End Offset**: nonnegative distances from the chosen start/end to the usable interval, measured to hole centers. They do not guarantee solid material beyond each hole.
- **Position**: additional nonnegative distance from Start Offset to the first center. It is not a modulo phase. If offsets consume the interval, the command reports an error. One center is allowed on a zero-width retained interval of an open, nondegenerate path.
- **Reverse Path**: measure from the other end; reverse the tangent as well. The underlying evaluator defines forward direction; a BRep edge uses its own evaluator, not the underlying curve's potentially different direction or full extents.
- **Orientation → Fixed**: hole axes follow sketch X plus Hole Angle. **Tangent**: follow the derivative in the chosen direction plus Hole Angle. Circles hide Orientation and Hole Angle. A singular tangent is rejected in Tangent mode; Fixed does not need a derivative.
- Closed paths start at the evaluator seam. The end of the retained interval is exclusive on a closed path, preventing a duplicate seam center. An exact physical join is also recognized for nonperiodic splines. A short closing remainder can violate Web Thickness; adjust Position/offsets/spacing or hole size. The implementation reports the conflict rather than dropping holes or changing the spacing.
- Start Point, Spread Radius, Pattern Angle and X/Y Offset are hidden and inactive. Switching back restores their UI values. Programmatic Along Path settings combining these controls are rejected explicitly. Voronoi keeps its own distribution; selecting it makes path controls inactive.

All 12 repeating shapes use the same Cell contours as existing distributions. Fast Preview, Full Preview, Sketch, Extrude and Feature resolve the same placements through `model.layout_settings`. Web checking uses enclosing circles (exact for round holes, conservative for every other shape), includes all nearby hole pairs, nonadjacent path sections and the closing seam, and occurs before exact trim. It can reject a noncircular/partial layout that would pass a contour-specific check. Trimming only removes material from each hole, so accepted enclosing bounds preserve the minimum web. No holes are automatically skipped to resolve conflicts; boundary rejection remains normal existing behavior.

## Numerical and API choices

Context7 was queried first (`/autodeskfusion360/autodeskfusion360.github.io`); it returned no matching evaluator documentation. The following official references and installed read-only Python API definitions were checked instead:

- [CurveEvaluator3D.getLengthAtParameter](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_CurveEvaluator3D_getLengthAtParameter.htm): bounded path length.
- [CurveEvaluator3D.getParameterAtLength](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_CurveEvaluator3D_getParameterAtLength.htm): distance from a starting parameter, then `getPointAtParameter` for each hole. Uniform spline parameters and stroked polyline chord lengths are **not** used as arc length. Autodesk does not expose a solver tolerance in this method; no stronger accuracy guarantee is claimed.
- [CurveEvaluator3D](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_CurveEvaluator3D.htm): `getFirstDerivative` determines tangent orientation.
- [CurveEvaluator3D.getStrokes](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_CurveEvaluator3D_getStrokes.htm): maximum curve-to-segment deviation supports checking the **whole curve**, not just candidate centers/endpoints, against the source plane.
- [NurbsCurve3D.isClosed](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_NurbsCurve3D_isClosed.htm): geometric closure. BRep edges use their bounding vertices; co-located endpoints within `EPS=1e-9 cm` also denote a physical seam.
- [CustomFeatureInput.addDependency](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_CustomFeatureInput_addDependency.htm): native path entity dependency for timeline ordering and recompute. This API remains Autodesk Preview API, as in existing Feature mode.

Lengths are cm, angles radians. Planarity strokes have maximum deviation `1e-5 cm` (0.0001 mm); stroke vertices must be within `9e-5 cm` of the source plane, leaving room for that deviation inside a `1e-4 cm` (0.001 mm) total plane tolerance. Hole centers are also checked at their actual evaluated positions. Paths of length ≤0.001 mm are rejected. Coincident samples and all unsafe webs are rejected; the clearance predicate allows only the existing geometry `EPS=1e-9 cm` numerical allowance. A derivative magnitude ≤1e-12 or a relative out-of-plane tangent component >1e-6 is rejected. These are explicit implementation thresholds, not claims about Autodesk kernel accuracy.

Sketch `.geometry` is evaluated in sketch coordinates and explicitly transformed with `sketchToModelSpace`; BRepEdge `.evaluator` is evaluated in source-component coordinates. The explicit source-plane basis projects positions/vectors to 2D. `.worldGeometry` is deliberately avoided: the installed descriptions use different assembly-space conventions for fitted and control-point splines. Same-component selection is the first-stage boundary, and Feature requires an unambiguous occurrence when creating its path dependency. Moved/rotated planes and component occurrences require native verification.

Both placement count and returned planarity stroke count are capped at 100,000; Maximum Holes still caps accepted holes at 5,000. A spatial hash checks nearby enclosing bounds without comparing every hole pair. The kernel creates its stroke array before Python can check that returned count; timing and cancellation of exceptionally complex splines remain native acceptance items. The renderer owns a one-entry path-sampling cache keyed by path identity, body/sketch revision, plane basis and distance/orientation settings. Color, presentation, hole dimensions and Extrude-only changes reuse samples; geometry settings still invalidate Cells as needed. Final CAD rereads the path and region, then may reuse only matching immutable Cells through GeometryCache. No native output bodies or stale evaluators enter that cache.

## Feature persistence and compatibility

The native path is stored as dependency `path`, never as a JSON object/token snapshot. New Feature nodes expose Path Spacing, Path Start Offset, Path End Offset and Path Position as model parameters, including expressions. Reverse/orientation are stored in schema-1 metadata. Transient samples are excluded from both Feature metadata and sketch attributes. Recompute reevaluates the live path. Edit Feature can replace a path, repair a missing path, or switch to another distribution, removing the path dependency. Removing Path while Along Path stays active is a validation error; Cancel relies on the existing native command transaction.

Schema 1 and existing identifiers are preserved. Old Feature nodes without path fields/parameters use defaults and retain their existing distributions. Switching such a node to Along Path is explicitly rejected before changing its metadata/dependencies: the API cannot add the four new native parameters to an existing node. Recreate it to use Along Path, so path expressions never silently lose parameter-driven recompute. Native create/recompute, dependency remapping across topology changes, Edit Feature rollback and save/reopen remain unverified.
