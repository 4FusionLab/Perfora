# Выпуск Perfora

[English](PUBLISHING.md)

Релизы собираются workflow [Check and release](https://github.com/4FusionLab/Perfora/actions/workflows/ci.yml).

## Подготовка версии

1. Определите следующую числовую версию `MAJOR.MINOR.PATCH` с помощью GitVersion 6.8.2 (`dotnet-gitversion /showvariable MajorMinorPatch`). Манифест Fusion в репозитории не переписывается: при упаковке релиза эта версия записывается в манифест внутри ZIP.
2. Обновите `CHANGELOG.md`, оба README и `docs/releases/vVERSION.md`. Укажите установку, фактические проверки, методику измерения производительности и существенные ограничения.
3. Выполните модульные тесты, проверку компиляции и `python3 install.py --zip --version X.Y.Z`. Проверьте соответствие манифеста в архиве, имени ZIP и контрольной суммы GitVersion; также проверьте две установки во временный `--api-root`, включая резервные копии.
4. Выполните необходимые CAD-проверки в отдельных несохранённых документах Fusion. Заполните матрицу приёмки из `CONTRIBUTING.md`, включая реальные OK/Cancel, Undo/Redo, редактирование штатного Extrude, пересчёт и редактирование Feature и локальное повторное открытие F3D. Запишите версии Fusion и ОС и различайте нативный CAD и CI Python. Никогда не заявляйте невыполненную CAD-приёмку Windows или проверку облачного сохранения.
5. Снимите изображения продукта в реальном Fusion с тем же нейтральным фоном, кадрированием и палитрой, что в существующей галерее. Проверьте реальную геометрию; не иллюстрируйте недоступные возможности.
6. Проверьте финальные изменения на наличие частных файлов, учётных данных, локальных путей, отчётов, кешей, резервных копий и ресурсов Autodesk, затем отправьте проверенный коммит в `main`.

## Каналы релизов

Серия 0.x остаётся экспериментальной и публикуется как предварительные выпуски. Версия 1.0.0 — первый стабильный выпуск. Версии с MAJOR >= 1 являются обычными GitHub Releases (`prerelease=false`) и явно помечаются Latest. Канал релиза аддона не меняет жизненный цикл используемых API Autodesk: Custom Feature API остаётся Autodesk Preview API.

Сопровождающий выбирает канал релиза. Записи о проверках описывают фактически проверенные платформы; CI Windows не подтверждает нативную CAD-работу Fusion. Невыполненные проверки отдельных платформ остаются документированными, в том числе для стабильных версий.

## Автоматическая публикация

Push в `main` запускает проверки компиляции, геометрии, установки и упаковки на Linux, macOS и Windows. Для публикации нужны подходящие изменения поставляемых файлов после последнего опубликованного релиза (или исходный диапазон push, если ZIP-релиза ещё нет). Push только документации может повторить ранее пропущенный выпуск с изменениями продукта, но сам по себе релиз не создаёт. Pull requests выполняют те же проверки без прав публикации.

Задание версии один раз определяет `MajorMinorPatch` через GitVersion. Все три задания ОС собирают ZIP с этой версией, а задание релиза использует её после успешных проверок. При наличии используются проверенные заметки конкретной версии; иначе общий Action создаёт заметки из истории Git. Созданный ZIP и встроенный манифест Fusion используют эту числовую версию. `scripts/release.py` определяет канал по числовой версии (старые 0.x — экспериментальные), загружает ZIP и SHA-256, скачивает оба для проверки байтов и публикует с нужными признаками prerelease/Latest. Только это задание имеет `contents: write`; оно использует встроенный токен GitHub Actions. Личный токен в проекте не хранится.

Существующая опубликованная версия неизменяема. Повтор неудачной загрузки допустим только для черновика того же точного коммита. Черновик для другого коммита останавливает публикацию для проверки. Перед созданием релиза задание также отказывается повторно использовать тег Git, уже указывающий на другой коммит. Никогда не перемещайте опубликованный тег и не заменяйте его файлы для исправления дефекта; публикуйте новую версию патча.

## Проверка публикации

Проверьте задания всех трёх ОС и задание релиза. Сверьте тег релиза, целевой коммит, состояние черновика, канал и ссылку Latest. Скачайте `Perfora-VERSION.zip` и `.sha256`, сравните их байты с проверенным дистрибутивом, изучите манифест и содержимое и дважды установите пакет во временный API root для проверки резервных копий. Убедитесь, что оба README, заметки к релизу и все связанные скриншоты отображаются на GitHub.
