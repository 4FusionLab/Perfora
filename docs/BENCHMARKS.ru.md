# Измерения производительности Perfora 1.0

[English](BENCHMARKS.md)

Измерено 24 октября 2026 года на macOS arm64, Fusion 2706.1.14 (macOS 27.0.1). Результаты сравнивают зафиксированный снимок разработки до оптимизации с оптимизированной геометрией, поставленной в 1.0. Оба снимка уже содержат Circular, Start Point, Spread Radius и размещение Tangential. **Базой не является опубликованный релиз 0.2.0.** Отпечатки исходников и исходные измерения находятся в [v1.0.0.json](benchmarks/v1.0.0.json).

## Генерация геометрии на чистом Python

Каждое значение — медиана трёх чередующихся измерений до и после со свежими Region и Settings. Подготовка индекса включена. Измеряется `geometry.generate`; рендеринг, создание нативного эскиза, обрезка BRep и Extrude исключены. Каждый образец проверяет совпадение ячеек и координат контуров. Отдельная матрица из 511 случаев не нашла различий в ячейках, координатах и соответствующих ошибках.

| Сценарий | Отверстий | До, мс | После, мс | Ускорение |
| --- | ---: | ---: | ---: | ---: |
| `tiny_circle` | 1 | 0.041 | 0.036 | 1.14× |
| `tiny_triangle` | 1 | 0.060 | 0.052 | 1.17× |
| `rect_circle` | 709 | 6.330 | 3.409 | 1.86× |
| `rect_hexagon` | 709 | 34.005 | 10.588 | 3.21× |
| `disk_hexagon` | 253 | 1282.353 | 96.812 | 13.25× |
| `disk_ellipse` | 45 | 4027.185 | 263.233 | 15.30× |
| `annulus_circle` | 72 | 107.009 | 13.573 | 7.88× |
| `disk_circular_circle` | 223 | 176.663 | 15.299 | 11.55× |
| `dense_hexagon` | 3831 | 178.721 | 53.161 | 3.36× |
| `voronoi` | 1041 | 269.651 | 125.366 | 2.15× |

`rect_*` использует область 120 × 250 мм; `disk_hexagon` — диаметр 120 мм; `disk_ellipse` — диаметр 80 мм. Размер отверстия по умолчанию — 5 мм, зазор 1,5 мм, отступ от края 3 мм. Плотный случай шестиугольников использует отверстия 2,6 мм и зазор 0,3 мм. `bounded_voronoi` использует очень большую границу с ограничением зоны 16 мм, чтобы проверить локальную генерацию кандидатов. Определения сценариев можно повторно запустить с помощью [scripts/benchmark_layout.py](../scripts/benchmark_layout.py).

Результат 15,30× для эллипсов относится только к этому пути генерации Python. Это **не** заявление об ускорении каждой команды или нативной операции с телом в 15 раз. В малых нагрузках есть шум на уровне микросекунд; семь дополнительных чередующихся серий по 1000 полных генераций показали 37,34 → 30,44 мкс для одной окружности и 55,70 → 47,44 мкс для одного треугольника.

## Нативный Fusion: первый Fast Preview и последующее построение

Одно парное измерение на сценарий в одном нативном сеансе Fusion. Построение измерялось после Fast Preview: базовая версия создаёт ячейки заново; оптимизированная повторно использует неизменяемые ячейки, но заново читает текущий источник и выполняет нативное построение. Число отверстий, площади профилей и координаты предпросмотра совпали (допуск координат 1e-7 см).

| Сценарий | Отверстий | Fast до → после, с | Построение до → после, с |
| --- | ---: | ---: | ---: |
| Шестиугольники в круглой границе | 253 | 1.148 → 0.104 | 2.453 → 2.193 |
| Эллипсы в круглой границе | 45 | 3.424 → 0.262 | 3.683 → 0.263 |
| Малая ограниченная касательная раскладка | 7 | 0.058 → 0.054 | 0.105 → 0.107 |

В последнем случае заметного ускорения построения нет. Создание нативных эскизов и кривых может занимать основное время при узорах из шестиугольников. Результаты зависят от оборудования, сложности границы, версии Fusion, поведения нативного API и кеширования. Время CAD в Windows и нормированные по оборудованию результаты не заявляются.

## Проверки кеша и цвета

Нативные регрессионные проверки подтверждают, что Fast → построение повторно использует ячейки, но текущие расстояния Extrude по-прежнему влияют на объём; Holes избегает булевых операций только для Panel; изменения ревизии источника и перемещение плоскостей сбрасывают соответствующие данные. Preview Color меняет только представление. Тест с 709 шестиугольниками проверяет все шесть нативных значений RGB без повторной генерации ячеек; измерение API меньше миллисекунды не включает обновление экрана и не гарантирует задержку взаимодействия.

## Повторение измерений текущей генерации

```sh
python3 scripts/benchmark_layout.py --repeat 3 --output /tmp/perfora-benchmark.json
python3 scripts/benchmark_layout.py --baseline /path/to/frozen/geometry.py --repeat 3
```

Исторический базовый вариант имеет отпечаток в исходных данных и намеренно не поставляется как дополнительная реализация. Аргумент базовой версии должен указывать на совместимый снимок с той же схемой Settings и Region. Для нативных измерений требуются Fusion и `tests/fusion_optimization_regression.py` с совместимым `baseline_path`; одни замеры Python не подтверждают поведение CAD.
