# Визуальное принятие Distribution v2

**Статус: офлайн-кандидат, ожидает визуального принятия пользователем.**
Исходная база — `07e7184`, отдельная ветка `codex/distribution-visual-acceptance`.
Загруженная копия Fusion и параллельная ветка органических форм не изменялись.
Установленное дополнение нельзя переводить на новые режимы до принятия демо.
Алгоритмы кандидата находятся в `Perfora/distribution_fields.py`; публичный
`geometry.generate()` выбирает их по `distribution_revision=2`. По умолчанию
сохраняется revision 1. Демо и будущий адаптер Fusion получают один список Cell;
новые поля сериализуются обычным Feature payload.

## Решения для оценки

- Сохранять ритм целого поля. Конфликт зазоров меняет шаг/число рядов всего
  поля, а не удаляет отдельное отверстие из регулярного ряда. По границе
  отбираются только целые отверстия с Edge Offset.
- Contour: замыкать ряд равномерным целым числом отверстий, проверять хорды,
  завершать заполнение до узких остатков у медиальной оси. Внутри остаётся
  осмысленное сплошное ядро. Геометрия уровней — прежнее приближённое поле
  расстояний, не подмена точным CAD-offset.
- Fan: общий внутренний радиус и общий радиальный шаг всех лучей. Рядом с
  вершиной нет россыпи пропущенных отверстий. Пустая дуга у вершины намеренна.
- Phyllotaxis: сохранять каждый индекс спирали Фогеля. При тесноте менять
  масштаб всего поля, сохраняя золотой угол и узнаваемые парастихи.
- Poisson Disk: существующий алгоритм сохранён. Нерегулярность здесь является
  смыслом раскладки; делать его регулярным нет оснований.
- Wave: отсчёт длины дуги от центра поля, одинаковые фазы соседних рядов,
  устойчивость при изменении границы, необязательная касательная ориентация щелей.
- Chevron: зеркальные пары, а не конфликтующие отверстия в общей вершине.
  Касательная ориентация даёт аккуратный центральный шов.
- **Running Bond не является самостоятельной семьёй.** По замечанию пользователя
  он объединён в демо с Staggered как Row Shift. 1/2 совпадает с шахматкой
  при равных шагах; 1/3 — параметр сдвига рядов. Установленный runtime не менялся.
- Between Curves: общие станции между направляющими вместо независимого числа
  отверстий в каждом ряду. При тесноте меняется число целых колонок/рядов.

## Как читать демо

Показаны точные круги Ø 2.5 mm и щели 1.7 × 5.2 mm. Web Thickness — 1.2 mm,
Edge Offset — 1.8 mm. Размер основной панели — 120 × 100 mm. Contour имеет
скруглённый некруглый источник; Phyllotaxis — круг Ø 93 mm. Физический масштаб
на растровых листах одинаковый. Растровые листы показывают щели по касательной,
а Phyllotaxis и Poisson Disk — круги; переключатель позволяет честно сравнить
одинаковые формы во всех раскладках.

«Прежний алгоритм» исполняет настоящий генератор из базы при тех же размерах
отверстий, границе, зазоре и параметрах мотива. Ориентация у прежних вариантов
фиксированная, поскольку следования касательной там нет. У кандидата шаг может
увеличиваться при решении коллизий; это отражается на количестве отверстий.
Это не обещание сохранения плотности. Линии построения не являются прорезями.

Файл включает все 12 пунктов из реестра LAYOUTS команды: четыре прежних режима
и восемь новых. Реестр читается без adsk; неизвестный режим останавливает сборку
вместо молчаливого пропуска. Along Path вызывает настоящие sample_path и
generate_path с аналитической дугой. Voronoi — Hole Shape, а не Distribution.

Версия 2 ещё не является готовой CAD-функцией: демонстрационные источники заданы
явно; нет Trim частичных отверстий, CAD, перевода на поверхности или новых
полей нативного диалога. Круги/щели проверяются точным
расстоянием между капсулами; у остальных повторяемых форм версия 2 проверяет
описанные окружности, сохраняя консервативную упаковку. Нативные пути для этих
форм требуют отдельной проверки после принятия визуального направления. Повороты криволинейных отверстий,
совместимость старых Feature и сохранение seed потребуют отдельного этапа.
Старые Feature нельзя молча пересчитывать новым алгоритмом.

Circular в общем тесте заполняется от центра: Start Radius = 0, ровно одно
центральное отверстие для круга и щели. Начальный демонстрационный отступ 8 mm
убран после замечания пользователя. Ненулевой Start Radius остаётся штатной
настройкой существующего кругового генератора, а не новым ограничением.

## Воспроизведение

```sh
python3 -m unittest discover -s tests -p test_distribution_study.py -v
python3 scripts/visual_distribution_test.py --output /absolute/path/distributions.html
```

Основной результат — **один автономный HTML** со всеми координатами, хешами
исходных модулей и оформлением. Сеть и сервер не нужны. Есть общий обзор,
отдельная раскладка, круги/фиксированные/следующие рисунку щели, сравнение
прежней версии и кандидата, линии построения, сдвиг 1/2 либо 1/3.

Геометрия, тесты и HTML-экспорт не имеют сторонних зависимостей. Если вместо
`.html` передать каталог, создаётся дополнительный комплект. Только экспорт PNG использует
локально установленный Pillow и шрифт Helvetica macOS; это не зависимости
дополнения. Экспорт создаёт `distribution-demo.html` (интерактивный фрагмент),
три PNG, точные координаты `data.json` и измерения `metrics.json`. Результаты
экспорта хранятся вне Git/дистрибутива. Шаблон и генератор находятся в этой папке.

Проверки включают независимую полную попарную проверку реального зазора всех
36 базовых комбинаций, совпадение с публичным ядром, детерминизм, непрерывность лучей Fan, сохранение индексов
Phyllotaxis, неподвижность Wave при обрезке области, общие колонки Between Curves
и два дополнительных уровня плотности для каждой раскладки. Локальная
производительность не является временем Fusion.

## Проверка 25 октября 2026

172 локальных теста проходят, включая 12 проверок этого стенда. Для 36 базовых
сочетаний всех Distribution с кругами и щелями выполнен независимый полный
перебор пар реальных контуров; выдержаны Web Thickness и Edge Offset. Проверены
перенос/поворот источника, сохранение ревизии в метаданных, прежняя ревизия по
умолчанию и центр Circular. Браузерная проверка подтверждает 12 панелей,
сравнение, смену форм, линии построения и Row Shift; на ширине 360 px нет
горизонтального переполнения. Реальные CAD/UI-проверки намеренно не запускались.
